# ML-001 — Synthetic ML notebook and exported UI insights

**Scope revision:** September 21, 2026 two-day demonstration. Supersedes this task's prior full-product launch requirements. Status remains PROPOSED; architecture/implementation/review are not certified by this specification.

## User-visible outcome

An inspectable notebook demonstrates a lightweight model on synthetic data, and the visible readiness trajectory uses the notebook's actual saved outputs.

## Required scope

Create a small reproducible synthetic dataset and data dictionary, a runnable notebook with exploration, lightweight offline training, held-out evaluation and limitations, plus scenario prediction exports. Connect those saved outputs to the existing trajectory/factor UI. Include a Why flagged? detail and a two-state transportation what-if comparison from notebook-generated outputs. Target a small CPU run; no hosted ML service.

## Deferred

Production model quality gates, large 75,000-encounter pipeline, mandatory LightGBM/SHAP/calibration, online inference, adaptive outreach policy, clinical validation and subgroup fairness claims.

## Architecture and contract guidance

Offline files under ml/ belong to the assigned ML/backend worker; frontend owns UI integration and its bundled copy. Proposed export: ml/artifacts/demo-insights.json; bundled copy: frontend/src/data/ml-insights.json. Bind copies by content/hash. The typed artifact schema includes scenario checkpoint, score meaning, factors, feature values, model/dataset version and generation time. Include baseline/variant input rows and actual scores/factors under the same model version; frontend comparison state is independent of the real scenario. No prediction endpoint or database table is needed.

All frontend work preserves [the approved visual system](../design/DESIGN_SYSTEM.md). Design-required work is a compatibility/extension plan with the existing digest gate. The architect must record actual impacts, execution controls and scope before BUILD_READY; the guidance here is not a completed architecture report.

## Verification and risk

SMOKE; LOW risk for locally generated synthetic data and trusted artifacts. Execute the notebook from clean inputs, inspect split/leakage checks and verify exact UI/export agreement. No minimum performance claim is prescribed.

- FLOW-001

## Acceptance criteria

1. The repository includes a reproducible synthetic dataset, generator or generation cells, seed, data dictionary and explicit synthetic-data limitations under ml/. It contains no real patient data; inspect the files.
2. A runnable notebook explains the problem, target, data exploration, feature availability, patient-separated train/test split, simple baseline, lightweight model training, held-out results and limitations. Restart-and-run succeeds on the documented environment.
3. Evaluation reports actual baseline/model metrics and a confusion matrix or appropriate classification plots, with sample counts and split seed. No tuned-on-test or invented numbers, clinical efficacy or calibrated-probability claim; inspect notebook outputs and leakage assertions.
4. The notebook scores the T-7/T-2/T-1 scenario using the fitted model and exports those actual predictions with factors and feature values. Identity is not a feature; future replies/outcomes cannot leak into earlier scores. Do not hand-edit outputs to force a rising trajectory.
5. The UI reads the exported checkpoint scores/factors and shows the same values as the saved artifact; verify a content/hash match and browser spot-check at each checkpoint. No inference service is required during presentation.
6. The staff view offers a concise source/evidence path to the notebook, synthetic-data metrics and limitations. Label scores as synthetic-data model output; explain associations without implying clinical urgency, causation or SHAP if not computed.
7. Explicit patient concern still opens human-owned work regardless of score; absent or malformed insight JSON shows unavailable insights without blocking workflow. Verify the error state and override.
8. Notebook, dataset and result links open, and the saved exported insights render offline with the existing visual language; record notebook execution and frontend smoke evidence.

9. Clicking Why flagged? at a scenario checkpoint reveals up to three available exported factors with readable feature values and a suggested supportive next action. Factors match that checkpoint's notebook output; next-action guidance follows the documented workflow rule and is not falsely labeled learned channel selection. Verify all three checkpoints and missing-factor behavior.
10. The notebook exports a baseline and transportation-available variant from the same fitted model with all other features held fixed, plus both input rows, actual scores, model identity and factor data. A two-state what-if control shows those saved outputs and their actual difference; no forced decrease, causal benefit or calibrated clinical-risk claim. Verify notebook/export/UI parity for both variants.
11. The what-if comparison operates offline, exposes no arbitrary-input inference endpoint and does not change the actual plan, readiness graph, outreach history or live-delivery state. Reset/exit returns to the actual scenario; missing comparison output disables the comparison with an explanation. Verify isolation, keyboard use and reset.
